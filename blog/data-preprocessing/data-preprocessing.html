Data preprocessing.

How messy real-world data becomes clean, consistent, model-ready input — with simple examples and Python.

Chanupa Deshan · September 5, 2026 · Beginner Guide

ON THIS PAGE

THE CORE IDEA

Machine-learning models work with numbers and structured representations. Data preprocessing is the process of turning messy real-world data into inputs the model can actually learn from.

Real-world data is rarely clean.

You may have empty cells, duplicated rows, text where numbers should be, different units, inconsistent categories, huge outliers, images with different sizes, or dates stored as plain strings.

A machine-learning model does not automatically understand what these problems mean.

That is why preprocessing is such an important part of machine learning.

In the previous article, we looked at supervised and unsupervised learning. Before either type of model can learn properly, we usually need to prepare the data first.

01What is data preprocessing?

Data preprocessing is the process of cleaning, organizing, and transforming raw data before giving it to a machine-learning model.

Think about cooking.

You normally do not take vegetables directly from the market and throw them into a finished dish. You wash them, remove damaged parts, cut them, measure them, and prepare them first.

Machine-learning data is similar.

Raw Data
   ↓
Clean the data
   ↓
Handle missing values
   ↓
Convert categories
   ↓
Scale or transform features
   ↓
Model-ready data

For example, imagine a customer dataset:

Example of raw data
Age Income City Purchased
2550000ColomboYes
?65000KandyNo
31colomboYes
99972000GalleNo

Immediately, we can see several problems:

  • One age value is missing.
  • One income value is missing.
  • Colombo and colombo may represent the same city.
  • An age of 999 is probably invalid.
  • The text values must eventually be represented in a form the model can use.

Preprocessing deals with these issues before training.

02Why does preprocessing matter?

A model can only learn from the information we give it.

If the input data is inconsistent, misleading, or badly formatted, the model may learn the wrong patterns.

Good model + bad data = bad result.

Suppose we are predicting house prices.

One row stores area in square feet:

1200

Another row stores area in square meters:

120

If we treat those numbers as the same unit, the model receives incorrect information.

Another common example is missing values:

Age = 25
Age = 42
Age = ?
Age = 31

Many algorithms cannot work directly with a missing value, so we need to decide how to handle it.

Preprocessing can help make data:

  • Consistent
  • Numerically usable
  • Easier for a model to learn from
  • Safer to evaluate
  • More similar between training and real-world prediction

03A simple and safe preprocessing workflow

A beginner-friendly workflow looks like this:

1. Understand the problem
2. Inspect the data
3. Split into training and test data
4. Learn preprocessing from training data
5. Apply the same preprocessing to test data
6. Train and evaluate the model

The order matters.

For example, if we calculate the mean of a feature using both training and test data, information from the test set has already influenced the training process.

This can make evaluation look better than it really is.

A safer pattern is:

Training Data
     ↓
Learn mean / median / scaling / categories
     ↓
Store the transformation

Test Data
     ↓
Reuse the transformation learned from training data

This idea becomes especially important when we discuss data leakage later.

04Handling missing values

Missing values are extremely common.

For example:

Customer ages
Customer Age
A22
B28
CMissing
D34

There are several possible approaches.

Option 1: Remove the row

If only a tiny number of rows are missing and losing them will not hurt the dataset, removing those rows may be reasonable.

22
28
Missing  ← remove
34

But if many values are missing, deleting rows may throw away too much useful information.

Option 2: Fill with the mean

For numeric values, one simple method is to replace the missing value with the average.

22 + 28 + 34 = 84

84 / 3 = 28

Missing value → 28

Option 3: Fill with the median

The median is often useful when the data contains extreme values.

20, 22, 25, 27, 200

Median = 25
Mean   = 58.8

Here, the extreme value 200 changes the mean heavily, while the median stays near the center of the normal values.

Python example

import pandas as pd
from sklearn.impute import SimpleImputer

data = pd.DataFrame({
    "age": [22, 28, None, 34]
})

imputer = SimpleImputer(strategy="median")

data["age"] = imputer.fit_transform(data[["age"]])

print(data)

For categorical data, we might instead use the most common category or an explicit category such as Unknown.

05Converting categorical data into numbers

Many datasets contain text categories.

For example:

City = Colombo
City = Kandy
City = Galle

Most machine-learning algorithms expect numerical inputs, so we need a way to represent these categories.

Why not simply use 1, 2, and 3?

Colombo = 1
Kandy   = 2
Galle   = 3

This may accidentally suggest an order:

Galle > Kandy > Colombo

But cities do not have that kind of numerical order.

A common solution is One-Hot Encoding.

One-hot encoding
City Colombo Kandy Galle
Colombo100
Kandy010
Galle001

Now each city is represented without creating a fake ranking.

Python example

import pandas as pd
from sklearn.preprocessing import OneHotEncoder

data = pd.DataFrame({
    "city": ["Colombo", "Kandy", "Galle", "Colombo"]
})

encoder = OneHotEncoder(sparse_output=False)

encoded = encoder.fit_transform(data[["city"]])

print(encoded)

When categories have a real order, such as:

Low
Medium
High

an ordinal representation may make more sense because the order actually contains meaning.

06Feature scaling

Now imagine a dataset with two features:

Age       → 18 to 70
Income    → 25,000 to 500,000

The income values are much larger than the age values.

For algorithms that depend on distance or gradient-based optimization, this difference in scale can matter.

Suppose two customers are:

Customer A
Age = 25
Income = 50,000

Customer B
Age = 30
Income = 150,000

The numerical difference in income completely dominates the difference in age.

Scaling puts features onto more comparable numerical scales.

Standardization

Standardization transforms a feature so that it is centered around its training-set mean and measured relative to its standard deviation.

You do not need to memorize the formula immediately. The practical idea is:

Before scaling:
Age    → 18, 25, 40, 70
Income → 25000, 60000, 120000, 500000

After standardization:
Both features are represented on comparable scales.

Python example

from sklearn.preprocessing import StandardScaler

X_train = [[22, 30000],
           [35, 60000],
           [50, 120000]]

scaler = StandardScaler()

X_train_scaled = scaler.fit_transform(X_train)

print(X_train_scaled)

Important: not every model requires scaling.

Scaling is especially relevant for algorithms such as:

  • K-Nearest Neighbors
  • Support Vector Machines
  • Logistic Regression
  • Neural Networks
  • K-Means

Tree-based models such as Decision Trees and Random Forests usually do not depend on feature scale in the same way.

07What about outliers?

An outlier is a value that is very different from most other values.

Suppose customer ages are:

21
23
25
28
31
999

The value 999 is suspicious.

But not every unusual value is an error.

Consider transaction amounts:

Rs. 2,500
Rs. 4,000
Rs. 3,200
Rs. 850,000

The large transaction may be completely valid — and in a fraud-detection problem it might even be one of the most important observations.

Do not automatically delete every outlier.

Instead ask:

  • Is the value impossible?
  • Was it entered incorrectly?
  • Is it rare but valid?
  • Is the unusual value important for the problem?

08Preprocessing text data

Machine-learning models cannot directly work with a sentence in the same way humans read it.

Consider:

"This product is really good!"

Depending on the model, text preprocessing may include:

  • Fixing Unicode
  • Removing unwanted HTML
  • Tokenization
  • Lowercasing
  • Converting text into numerical vectors

But cleaning text too aggressively can destroy meaning.

For example:

"This product is good."
"This product is NOT good."

If we remove the word not, the meaning changes completely.

This is especially important for multilingual data. A preprocessing function that keeps only English characters would destroy Sinhala text.

A simple TF-IDF example

from sklearn.feature_extraction.text import TfidfVectorizer

texts = [
    "machine learning is useful",
    "deep learning is powerful",
    "machine learning uses data"
]

vectorizer = TfidfVectorizer()

X = vectorizer.fit_transform(texts)

print(vectorizer.get_feature_names_out())
print(X.shape)

Modern transformer models such as BERT normally use their own tokenizer. In that case, it is usually better to follow the preprocessing expected by the model instead of manually removing large parts of the text.

09Preprocessing image data

Images can also arrive in many different forms.

One image may be:

1920 × 1080

another:

640 × 480

and another:

224 × 224

Many neural networks expect a consistent input size.

Common image preprocessing steps include:

  • Correcting orientation
  • Converting to RGB
  • Resizing or padding
  • Converting pixels to numeric arrays
  • Scaling or normalizing pixel values

For a normal 8-bit RGB image, pixel values are usually between:

0 and 255

We may scale them to:

0.0 to 1.0

Python example

import numpy as np
from PIL import Image

image = Image.open("photo.jpg")
image = image.convert("RGB")
image = image.resize((224, 224))

pixels = np.asarray(image, dtype=np.float32) / 255.0

print(pixels.shape)
print(pixels.min(), pixels.max())

If you use a pretrained model, follow the exact preprocessing expected by that model. Some models require particular image sizes, normalization values, or channel ordering.

Data augmentation

During training, we can sometimes create slightly modified versions of images:

Original image
   ↓
Flip
Rotate slightly
Crop
Change brightness
   ↓
More training variation

This is called data augmentation.

But transformations must still make sense for the task. Flipping a cat image may be fine. Flipping an image containing readable text may change or destroy useful information.

10Preprocessing time-series data

Time-series data is data where order matters.

Examples include:

  • Daily sales
  • Temperature readings
  • Stock prices
  • Sensor measurements
  • Traffic volume

Suppose we have daily sales:

Monday    → 100
Tuesday   → 120
Wednesday → 115
Thursday  → 140

For forecasting, the past can be used to predict the future.

We might create a lag feature:

Lag feature example
Day Yesterday's Sales Today's Sales
Tuesday100120
Wednesday120115
Thursday115140

The key rule is simple:

Do not use future information to predict the past.

For this reason, time-series datasets are usually split chronologically.

Past data        → Training
More recent data → Validation
Newest data      → Test

A random split can accidentally allow information from the future to influence training.

11One of the biggest mistakes: data leakage

Data leakage happens when information that should not be available during training somehow enters the model-building process.

This can produce excellent-looking evaluation scores that disappear when the model is used in the real world.

Here is a simple example.

Suppose we want to predict whether a student will pass an exam.

Useful features might be:

Attendance
Study hours
Previous grades

But imagine we accidentally include:

Final exam mark

The model can easily predict whether the student passed because the answer is already hidden inside the input.

That is leakage.

Leakage during preprocessing

Leakage can also happen more subtly.

Wrong approach:

Entire dataset
     ↓
Calculate mean and standard deviation
     ↓
Scale everything
     ↓
Split into train and test

Better approach:

Split data first

Training data
     ↓
Learn preprocessing values
     ↓
Transform training data

Test data
     ↓
Reuse values learned from training data

This is why tools such as scikit-learn's Pipeline are useful.

A practical pipeline example

from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

model = Pipeline([
    ("fill_missing", SimpleImputer(strategy="median")),
    ("scale", StandardScaler()),
    ("classifier", LogisticRegression())
])

model.fit(X_train, y_train)

predictions = model.predict(X_test)

The pipeline helps keep preprocessing and the model together, which makes training and prediction more consistent.

12A practical preprocessing checklist

Before training a model, I like to ask these questions:

  • Are the column types correct?
  • Are the units consistent?
  • Are there missing values?
  • Are there duplicate rows?
  • Are categories written consistently?
  • Are there impossible or suspicious values?
  • Do categorical variables need encoding?
  • Does the model require feature scaling?
  • Was preprocessing learned only from training data?
  • Could any feature reveal information from the future?
  • Will the same preprocessing be used when the model is deployed?

Different data types need different preprocessing

Common preprocessing by data type
Data Type Common Steps
TabularMissing values, encoding, scaling, duplicates, outliers
TextUnicode handling, tokenization, vectorization
ImagesResize, crop/pad, pixel conversion, normalization
Time SeriesSort by time, lags, rolling features, chronological split
AudioSample rate, channels, windows, spectrograms or learned features
VideoFrame sampling, resizing, temporal alignment

13Final thoughts

Data preprocessing is not just about making a dataset look clean.

It directly affects what the model sees and therefore what the model can learn.

The main idea is:

Raw Data
   ↓
Understand it
   ↓
Clean it
   ↓
Transform it safely
   ↓
Train the model
   ↓
Use the same preprocessing in production

The exact preprocessing steps depend on the data and the model.

A Decision Tree may not need the same scaling as Logistic Regression. A BERT model may need very different text preparation from a TF-IDF model. A pretrained image model may expect a very specific normalization process.

So the goal is not to apply every preprocessing technique you know.

The goal is to apply the right preprocessing for the data, the model, and the problem.
